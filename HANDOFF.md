Since 2026-07-30 the **CSP is inlined from the same variable** (D-058), so a mis-pinned build now also serves a `connect-src` naming the wrong project — which is a louder symptom of the same mistake, not a new one. All three Playwright configs now pin, but `playwright.config.ts` is one of the uncommitted files below, so a fresh clone does not. GOTCHAS carries the variable list and the Windows `$env:VAR = ""` deletion trap that makes a pin look broken.

`pnpm supabase:reset` cannot be guarded and destroys whatever project the working directory names — the repo root names the test project, `live/` names the real one. **Back up through the `/recovery` route before anything destructive, and never set `ALLOW_DESTRUCTIVE_TESTS=1` merely to get a green run.**
